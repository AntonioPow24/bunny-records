- **Proponer, no imponer.** Todo lo que hace el sistema es un punto de partida: textos, idioma, límites o animaciones se pueden cambiar en cada proyecto sin pelearse con él.
- **Dar el código en lugar de esconderlo.** Tarde o temprano un proyecto necesita algo distinto. Si el componente vive dentro del proyecto, se adapta en un momento.
- **Accesible desde el principio.** Elegí una base pensada para teclado, lectores de pantalla, distintos idiomas y pantallas táctiles, porque añadirlo al final siempre sale peor.
- **Gráficas que todo el mundo pueda leer.** Cada gráfica tiene también su versión en tabla y unos colores que se distinguen aunque se tenga daltonismo.
- **Prepararse antes de prometer estabilidad.** Antes de dar el sistema por estable, repasé nombres y opciones y dejé escrito cómo se harán los cambios futuros, para que nadie se lleve sorpresas.
